# 论文工作台 UI 设计说明

日期：2026-10-06
对应实现：`app/ccfa_gui/`（PySide6）
设计稿：`docs/design/exports/*.svg`（浅色）与 `docs/design/exports/dark/*.svg`（深色），
两份都由同一份生成器按色板产出，Figma 可直接导入
生成器：`docs/design/generate_mockups.py`

## 一、这个界面要回答什么

使用者打开工作台只关心三件事，界面结构就按这三件事排：

1. 我有哪些论文项目，哪个坏了？
2. 当前这篇卡在哪个阶段、哪个门禁、下一步该跑什么？
3. 有哪些事**只有人能决定**，答案该写到哪里？

因此是三栏 + 顶栏 + 状态栏：左栏项目、中栏当前项目的状态与检查结果、右栏对话。
三栏同时可见是硬约束——把项目列表做成下拉、把结果表做成弹窗，就等于让人
在"我有哪些项目"和"这篇什么状态"之间来回切换。

## 二、屏幕清单

| 稿件 | 状态 | 重点 |
| --- | --- | --- |
| `01-workbench-empty.svg` | 还没有项目 | 空状态给出创建命令，不装作有内容 |
| `02-workbench-project.svg` | 正常项目 | 徽章表达阶段/门禁/截止，结果表全绿 |
| `03-workbench-blocked.svg` | ccfa.yaml 坏了 | 红色徽章 + 单行原因，完整报错进结果表 |
| `04-human-checkpoints.svg` | 有待人工决定 | 每条 checkpoint 一个问题 + 一个落笔位置 |
| `05-settings-dialog.svg` | 设置 | provider 与工作流分区，保存为主按钮 |
| `06-chat-bubbles.svg` | 对话四种角色 | 你 / 助手 / 工具 / 错误各一条，工具条带 risk chip |
| `07-narrow-collapsed.svg` | 窄窗口（900×700） | 对话栏收起，详情栏占满；工具栏对话按钮露出关闭态 |

`04` 是设计上新增的界面：数据来自 `readiness.human_review.checkpoints`
（见 `docs/skillpack-format.md` 同一批工作）。它把"待人工"从 key 列表
变成可回答的问题，并把答案位置直接写出来。

## 三、设计令牌

全部取自 `app/ccfa_gui/theme.py`，生成器直接读同一个文件，所以设计稿与
实际样式不可能各走各的：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `ACCENT` | `#625fff` | 主按钮、focus 边框 |
| `INK` / `MUTED` | `#1a1a1f` / `#71717a` | 正文 / 次要说明 |
| `LINE` / `CANVAS` / `PANEL` | `#e4e4e7` / `#f7f7f8` / `#ffffff` | 发丝线 / 画布 / 卡片 |
| `PROBLEM` / `ADVISORY` / `OK` | `#d92d20` / `#b45309` / `#067647` | 三态语义色 |
| 字体 | Inter + Microsoft YaHei UI；代码用 JetBrains Mono / Consolas | |
| 圆角 | 卡片 6px，按钮 6px，徽章 4px | 上限 8px，不做大圆角 |
| 图标 | 线性图标，24 视框、1.75 描边、圆头圆角 | 几何数据在 `app/ccfa_gui/icon_paths.py` |

深浅两套色板定义在 `theme.py` 的 `LIGHT` / `DARK` 里，键名完全一致（有测试钉住）。
应用默认跟随系统配色，`CCFA_THEME=light|dark` 可覆盖（截图与测试用）。深色画布
`#141419`、面板 `#1e1e24`、主色提到 `#7c7aff` 以保住对比度，语义色整体提亮一档。

图标不是拍脑袋画的：`icon_paths.py` 里只有路径数据（无 Qt 依赖），app 用它渲染
`QIcon`，设计稿生成器用同一份数据画 SVG，两边不可能各走各的。产品标记是主色圆角
方块 + 三条白线，出现在工具栏最左侧。

## 四、组件契约

**工具栏**：40px 高，左侧刷新 / 设置，右侧项目计数（含"N 个无法读取"）。
最左侧是产品标记与「论文工作台」标题；刷新与设置带线性图标。

**项目行**：健康项 `● slug`；坏项 `▲ slug — 一行原因` + 红色前景，完整报错进 tooltip。
原因必须剥掉绝对路径，否则一行放不下。

协作状态用第二个字形：`◆ slug` + 琥珀前景，表示
`ccfa.readiness --collaboration-only` 报了问题（非 git 仓库 / 有未提交改动 / 无
remote / 无 CI workflows）。行里不再追加文字——侧栏最小 180px，任何后缀都会被
QListWidget 省略成半截——逐条原因与提交号放 tooltip，工具栏汇总
`N 个项目 · … · M 个有协作风险`。探针在后台线程跑（一次约 0.6s），结果按
generation 校验，过期结果丢弃。

**头部卡片**：项目名 17px 半粗；下面一行次要说明（模式 / 更新时间）；
再下面三个徽章：阶段、门禁、截止。坏项目时阶段与门禁徽章转红底红字，
截止徽章保持中性（未知不是错误）。

右上角是两个入口：打开目录与导出报告，都是 26px 图标按钮（文件夹 / 下载），
导出把 `ccfa.readiness --out` 的一页式报告写进 `reviews/readiness-<日期>.md` 并打开。
「截止」徽章显示倒计时（`剩 N 天` / `已逾期 N 天` / `今天截止`），绝对日期放 tooltip：
窄窗口徽章行只放得下短的，日期在报告与 tooltip 里都有。

**动作行**：主按钮只留一个（`运行 validate`），次要动作降级为白底按钮；
动作按钮排在一行**可换行**的流式布局里（`ccfa_gui/flow_layout.py`），中栏被挤窄时
换到第二行，不把标签省略成「运行 mileston」；结果量（`N 条结果 · M 条需处理`）
单独一行放在按钮下方，颜色跟状态走。

动作行是三类检查 + 一个阶段写操作 + 一个人工队列：`运行 validate`（主）、
`运行 milestones`、`运行 readiness`、`阶段流转`、`待人工复核`。`阶段流转` 是
唯一写盘的动作：弹窗里先选推进/回退（只列出 stage 表里合法的目标），原因必填，
回退时逐行列出要作废的产物；确认后走 `ccfa.state … --confirm`，成功后重新扫描并
重选同一个项目。readiness 是"这篇现在到底什么状态"的完整答案，
它把三段塞进同一张表：**维度**（六个）、**gate 结论**（只列非 `pass`，`blocked`
琥珀 / `fail` 红 / `error` 红）、**阻塞项**；横幅给出第一条阻塞与结论计数。

**结果表**：三列固定语义（来源 / 代码 / 消息），代码列用等宽字体并按
severity 上色，消息列超出截断并把全文放进 tooltip。

**对话面板**：引擎下拉在顶部，消息区自成一框，底部输入区 + 发送。
未配置 provider 时提示写在输入框上方，不弹窗打断。

**对话气泡**：一条消息一个圆角卡片，左上角是角色名，正文可换行可选中。
角色决定底色：`user` 主色淡底、`assistant` 普通面板、`tool` 灰底、
`error` 红底（角色名也转红）、`stopped` 琥珀底。工具消息把
`名字 [risk] -> outcome` 拆成三段：名字当角色名、risk 当 chip（按 outcome 上色），
outcome 作正文。列表项本身仍保留纯文本，脚本消费者不受影响。

正文按 **Markdown** 渲染（列表、强调、链接、代码围栏），代码用等宽字体；
代码围栏默认是"不折行"块，在 400px 宽的栏里会被裁，所以气泡渲染时把它改成
可折行，并按文档实际排版高度反算气泡高度。

**checkpoint 卡**：类型 chip（`approve` 灰 / `feedback` 琥珀）、右侧一个
`打开台账` 动作、问题一行、落笔位置一行（等宽 + 次要色）。
卡片只回答"要判断什么"和"写哪"，不在这里直接编辑台账。

**空白状态**：中栏没有项目可显示时，用一个居中图标 + 一行标题 + 一行提示
（例如创建论文的命令），而不是留一张空表。

## 四点五、动效

动效只用来解释**布局变化**，不做装饰：

| 变化 | 动效 | 时长 |
| --- | --- | --- |
| 对话栏收起 / 展开 | 动画最大宽度 0 ↔ 面板宽度 | 180ms，InOutCubic |
| 详情页切换（结果表 / 卡片 / 空白状态） | 新页面淡入 opacity 0→1，结束后移除图形效果 | 140ms |

规则：

- 不缩放、不弹跳、不淡出；切换是瞬时的，只有新内容淡入。
- 动效**不改状态**：动画结束回调负责把最大宽度与最小宽度恢复成常态。
- 减少动效：构造时 `animations=False` 或环境变量 `CCFA_NO_ANIM=1` 全部即时生效；
  窗口还没显示时也走即时路径（否则启动会出现一次无意义的滑动）。

**设置对话框**：标题 + 一句密钥存放说明，然后 provider 与工作流两个分区，
保存是唯一主按钮，取消降级。

## 五、状态与可读性

- 不用颜色单独承载信息：坏项同时有 `▲`、红色文字和一行原因文字。
- 结果表代码列颜色只是加速扫读，文字本身写明 `OK` / `错误` / `问题`。
- 长文本一律截断 + tooltip，卡片内不允许溢出（生成器里有 `clip()` 兜底）。
- 中英混排按基线对齐：中文用 sans、路径与标识符用 mono。
- 窄窗口（<1000px）先收起右栏对话，把宽度让给项目详情；工具栏的对话按钮可以
  手动叫回来，窗口重新变宽后自动规则重新接管（手动选择在跨过断点时清空）。
  三个栏位都显式设了最小宽度，否则详情栏的自然最小宽度会把窗口顶得比断点还宽。

## 六、怎么用这份设计

```powershell
# 重新生成浅色设计稿（只依赖 theme.py，不启动 Qt）
& app/.venv/Scripts/python.exe docs/design/generate_mockups.py

# 深色一套（写到 exports/dark/）
$env:CCFA_MOCKUP_MODE='dark'
& app/.venv/Scripts/python.exe docs/design/generate_mockups.py
```

Figma：`File → Import`（或直接把 `.svg` 拖进画布）。每个 `<g id="...">`
会变成一个可命名的图层，文字保持可编辑。

已导入的 Figma 文件：<https://www.figma.com/design/XpIadzobOUEEPimh31y0TC>
（五屏按列排布，都是可编辑矢量图层；`get_screenshot` 复核过导入结果与设计稿一致）。
早期那版说明里"没有配置 Figma MCP"已经过期：插件接上账号后 MCP 工具可用。

4. 对话气泡：五种角色各有底色与角色名配色，工具消息拆成名字 / risk chip /
